WHAT THIS IS (vs the flat cyan/white logo in pack01):
  The canonical AGENTSCII letters are rendered as MOLTEN METAL: each filled glyph cell carries a heat
value = vertical position within the letter (hot core, cooler crown + foot) + per-cell noise, mapped to
a density ramp (full block at the hot core -> sparse ░ at the cooling edges) and a WARM-ONLY fg wheel so
the mark shimmers like glowing metal instead of reading as flat colored ASCII. A molten glow pool sits
below the mark; embers rise ABOVE it into black void (FORGE's upward-dissolve motif); a framed title
card ("AGENTSCI // MOLTEN MARK") matches FORGE's framing so the two read as a set.

TECHNIQUE:
  PASS 1  TITLE CARD: framed_into() with warm subtitle in SGR 94, matching FORGE's framing.
  PASS 2  MOLTEN MARK: canonical AGENTSCII 5x7 glyphs (verbatim from make_logo.py) rendered with
    per-cell heat = vertical position + noise -> density ramp + warm fg wheel. The mark reads as
    glowing molten metal, not flat colored ASCII.
  PASS 3  GLOW POOL: a wide hot band below the mark, white-hot core fading to red at edges, with
    per-cell noise so it reads as molten flow not flat stripes.
  PASS 4  EMBER CASCADE: ~46 sparse bright embers rising above the mark into void, biased toward the
    mark's horizontal span so they read as rising FROM it, not uniform scatter.

WARM PALETTE (same gotcha as FORGE): warm = white(15)/yellow(3,11)/red(1,9) ONLY. No green/cyan in the
art field; the only cyan is sig_block's title line per house convention. In this guarded c() map index
11 -> bright yellow (93), so WARM=[15,11,9,3,1] is genuinely warm-only.

HYGIENE (verified): cp437 clean; control bytes {0x1b,0x0a} only; ends on standalone ESC[0m; all content
rows exactly 80 wide; SGR in house range. inspect_piece flags "internal gaps" on the sparse ember rows
and title strip interior -- that's INTENTIONAL (scattered embers rising into void + framed card),
confirmed via preview, not a fill bug.
